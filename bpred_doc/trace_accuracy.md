# Трейс-точность направления (Stage-2): эталонная модель предсказателя

Прямая оценка **точности предсказания направления** (как в CBP / black-parrot),
дополняющая цикловые замеры. Ветки реальных прогонов SCR1 сбрасываются в трейс, затем
офлайн-модель `bpsim` прогоняет тот же поток через набор алгоритмов и меряет
mispredict/accuracy. Это отвечает на вопрос «насколько точен предсказатель направления
и где потолок», отдельно от вопроса «сколько это даёт циклов».

## 1. Метод

- **Трейс из RTL:** tb под `-DSCR1_BP_TRACE` печатает на каждую retired **условную**
  ветку строку `BT <PC> <taken>` (ground truth из RTL). 16 бенчей Embench → трейсы,
  суммарно **5.03M условных веток**.
- **Модель `bpsim` (C):** сменные предсказатели направления:
  - `always-NT` — всегда не-взято (= направление No-BPU);
  - **`bimodal-2b`** — 1024×2-бит, индекс `PC[10:1]` — **точная конфигурация BHT SCR1**;
  - `gshare-Nb` — `PC[10:1] XOR GHR`, история 2/4/6/8/10 бит, та же 1024-таблица;
  - `gshare-16b/64K` — большая таблица (потолок ёмкости);
  - `local-2level` — 2-уровневый с локальной историей на PC.
- Валидация: `always-NT`-промахи модели = число взятых веток из RTL-трейса (ground
  truth), а `bimodal-2b` повторяет точную конфигурацию BHT — модель верна направлению
  SCR1. (RTL-`mispred` из BP_PROFILE — сквозной, включает BTB/RAS/цели, поэтому не равен
  изолированной точности направления — это разные величины.)

## 2. Результаты — accuracy направления (агрегат 16 бенчей)

| алгоритм | accuracy | mispred (из 5.03M) |
|---|---|---|
| always-NT (No-BPU) | 44.2 % | 2 805 652 |
| **bimodal-2b (BHT SCR1)** | **87.9 %** | 610 929 |
| gshare-4b (1024) | 89.5 % | 527 111 |
| gshare-10b (1024) | 90.9 % | 456 999 |
| local-2level | 92.5 % | 376 563 |
| **gshare-16b / 64K (потолок)** | **96.4 %** | 179 747 |

gshare-свип по ширине истории (1024-таблица, агрегат mispred): 2b→565K, 4b→527K,
6b→498K, 8b→478K, 10b→457K — длиннее история помогает, **но упирается в алиасинг**
1024-таблицы; большая таблица (64K) сразу даёт 180K (96.4%).

## 4. Выводы

1. **Точность направления BHT SCR1 = 87.9 %** (агрегат) — от 66.8 % (nettle-sha256) до
   99.4 % (depthconv).
2. **Есть запас точности, но он ограничен ЁМКОСТЬЮ, не алгоритмом.** Потолок (64K-таблица)
   = 96.4 %; у ряда бенчей (aha-mont64 72→99, ud 68→99.9, nettle-sha256 67→99) огромный
   разрыв bimodal↔потолок — это чистый **алиасинг** 1024-таблицы, а не непредсказуемость.
   gshare помогает умеренно (+1–3 %) в той же таблице; большая таблица/TAGE закрыли бы
   основной разрыв.
3. **Но эта точность НЕ конвертируется в циклы.** Из RTL-замеров ([[optimization_study]]):
   gshare улучшает точность (модель это подтверждает) и **ухудшает циклы**
   (frontend-bound + рассинхрон fetch-гейта); размер таблиц насыщён по циклам. То есть у
   направления есть headroom, но оно **не узкое место** — двойное подтверждение с RTL- и
   модель-сторон.
4. sglib/huffbench/wikisort имеют низкий потолок (90–93 %) — их ветки реально шумные
   (data-dependent), там не помогает ни ёмкость, ни история.

## 5. Против SoTA (CBP-NG, TAGE-SC-L)

Чтобы поставить нашу точность в контекст соревнований, собран фреймворк **CBP-NG
2025** (`github.com/AmpereComputing/cbp-ng`, `g++ -std=c++20 -lz`, флаг `-Wno-error`
для их reference-хедера) с эталонным предсказателем **TAGE-SC-L** (Seznec, 1531 Кбит).
Из CBP-трейса извлечены условные ветки (`BR_COND`) в наш формат `PC taken` (экстрактор
на `trace_reader.hpp`) и прогнаны через `bpsim` — так наш маленький BHT и SoTA
сравниваются на **одном стандартном трейсе**.

**Трейс `gcc_test` (493 313 условных веток):**

| предсказатель | память | accuracy | mispred |
|---|---|---|---|
| always-NT (No-BPU) | — | 45.9 % | 266 664 |
| **bimodal-2b (BHT SCR1)** | ~2 Кбит | **91.4 %** | 42 322 |
| gshare-2b (наш) | ~2 Кбит | 92.0 % | 39 413 |
| gshare-16b / 64K (потолок нашей схемы) | 128 Кбит | 94.0 % | 29 799 |
| **TAGE-SC-L (SoTA)** | **1531 Кбит** | **98.0 %** | 9 845 |

Свип размера на `gcc`: bimodal насыщается на **~91.6 %** (упор в алгоритм 2-бит, не в
ёмкость), gshare — плато **~94 %**. Дальше только TAGE/перцептрон.

**Что это значит.** Наш BHT берёт 91.4 % точности за **~2 Кбит**; SoTA TAGE-SC-L —
98.0 %, но ценой **×750 памяти** и несоизмеримой сложности (мн. тэг-таблиц +
статкорректор + loop + IMLI). Разрыв (91→98 %, ~4× меньше промахов) критичен для
больших OoO-ядер с глубоким конвейером (промах 15–20 тактов), но **на SCR1
бесполезен**: 3-ступенчатое in-order, промах ~2–3 такта, узкое место — фронтенд, и эта
точность в циклы не конвертируется. То есть наш предсказатель — **оптимален для своего
класса ядра**, а не «слабее TAGE».

Конвейер готов к любому CBP-трейсу: `./compile extract_trace -Wno-error` →
`./extract_trace <trace.gz> > t.trace` → `bpsim t.trace`. (Официальные CBP-16 BT9-трейсы
гейтнуты — подписка TAMU/NCSU; CBP-NG-трейсы доступнее.)
