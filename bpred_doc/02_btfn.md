# Часть 2 — BTFN (статический предсказатель, базовый слой)

Файл модуля: [`scr1_pipe_bpred.sv`](../src/core/pipeline/scr1_pipe_bpred.sv)
Точки вставки: `scr1_pipe_ifu.sv` (инстанс на выходе очереди + арбитрация).
Происхождение: адаптация `ibex_branch_predict.sv` (lowRISC Ibex, Apache-2.0).

---

## 0. Краткая теория (по книге Martínez Aceves)

**Статическое** предсказание — это фиксированное правило «взят/не взят», не
зависящее от истории исполнения. Классика — **BTFN (Backward-Taken /
Forward-Not-taken)**: условный переход **назад** (отрицательное смещение)
предсказываем как *взят*, **вперёд** — как *не взят*. Логика: переходы назад — это
почти всегда рёбра циклов, а цикл исполняется много раз, значит «взят» угадывает в
подавляющем большинстве итераций. Безусловные `jump` — всегда «взят» (они
безусловны по определению).

Роль в нашей иерархии: BTFN — **дефолт**, который работает *без всякой памяти* и
*до* того, как динамический BHT ([BHT](03_bht.md)) обучился. Когда запись BHT ещё не
обучена (`valid=0`) — направление берётся от BTFN. Это гарантирует разумное
предсказание с первого прохода.

---

## 1. Зачем он нужен (смысл)

BTFN отвечает на **оба** вопроса поздней ступени для *прямых* переходов:
1. **направление** (по правилу знака смещения, если BHT ещё молчит);
2. **цель** — вычисляет `target = PC + immediate` прямо из битов команды.

В отличие от BTB (§01), который **кэширует** цель, BTFN **вычисляет** её на лету —
он работает на выходе очереди, где команда уже вытащена и её биты доступны, так что
непосредственное смещение можно просто извлечь и сложить с PC. Модуль **чисто
комбинационный** (нет состояния → нет отката); `clk/rst_n` нужны только ассерту.

---

## 2. Принцип работы

Берёт `{bp_instr_i, bp_pc_i, bp_vd_i}` (команда, её PC, валидность) и выдаёт
`{bp_predict_taken_o, bp_predict_pc_o, bp_is_branch_o}`. Внутри:
1. извлекает непосредственные смещения всех форматов (B, J, CB, CJ);
2. детектит тип команды по opcode;
3. считает направление (jump → всегда взят; условный → BHT или BTFN-знак);
4. считает цель `PC + branch_imm`.

## 3. Разбор кода модуля (`scr1_pipe_bpred.sv`)

**Параметры фаз** (стр. 26–27) — так модуль вводился поэтапно:
`SCR1_BP_PREDICT_BRANCHES` (M2: включить условные RVI), `SCR1_BP_PREDICT_RVC`
(M3: включить сжатые). На M1 предсказывался только `JAL`.

**Извлечение смещений** (стр. 76–83) — verbatim из Ibex, по одному ассайну на
формат. Разберём на реальной команде `beq a0, a1, .+8` = `0x00B50463`:
```
imm_b_type = { {19{instr[31]}}, instr[31], instr[7], instr[30:25], instr[11:8], 1'b0 };
```
Формат **B-type** раскидывает биты смещения по кодировке; этот ассайн собирает их
обратно в число со знаковым расширением. Для `0x00B50463` он даёт `+8`. Младший
бит всегда `1'b0` — переходы кратны 2 байтам.

**Детект типа** (стр. 88–95):
```systemverilog
instr_b  = (instr[6:0] == 7'b1100011) & SCR1_BP_PREDICT_BRANCHES; // BRANCH (beq/bne/…)
instr_j  = (instr[6:0] == 7'b1101111);                            // JAL
instr_cb = SCR1_BP_PREDICT_RVC & (instr[1:0]==2'b01) & (instr[15:13] inside {110,111}); // c.beqz/c.bnez
instr_cj = SCR1_BP_PREDICT_RVC & (instr[1:0]==2'b01) & (instr[15:13] inside {101,001}); // c.j/c.jal
```
Здесь **opcode участвует** (в отличие от индекса BTB, где брался только адрес):
именно opcode отличает переход от арифметики.

**Выбор смещения цели** (стр. 98–107) — `unique case` по одному из четырёх типов.

**Направление** (стр. 109–121):
```systemverilog
`ifdef SCR1_BP_DYNAMIC
  cond_btfn  = instr_b ? imm_b_type[31] : imm_cb_type[31]; // знак смещения = назад?
  cond_taken = bp_bht_valid_i ? bp_bht_taken_i : cond_btfn; // BHT важнее, если обучен
  instr_b_taken = (instr_b | instr_cb) & cond_taken;
`else
  instr_b_taken = (instr_b & imm_b_type[31]) | (instr_cb & imm_cb_type[31]); // чистый BTFN
`endif
```
Ключевая строка — `cond_taken = valid ? bht : btfn`: **BHT переопределяет BTFN,
только если запись обучена**, иначе работает статическое правило знака. Это и есть
«BTFN как fallback динамики».

**Выходы** (стр. 124–128):
```systemverilog
bp_predict_taken_o = bp_vd_i & (instr_j | instr_cj | instr_b_taken); // jump всегда взят
bp_predict_pc_o    = bp_pc_i + branch_imm;                           // цель
bp_is_branch_o     = bp_vd_i & (instr_j | instr_b | instr_cj | instr_cb); // это переход?
```
`bp_is_branch_o` важен для §01: он позволяет IFU опознать переход на выходе очереди
даже когда BTFN сказал «не взят» — нужно для проверки BTB-steered слова
(`bp_steer_hit`).

**Ассерт** (стр. 130–135): под симуляцией проверяет, что тип команды one-hot.

## 4. Куда он вставлен в ядро (`scr1_pipe_ifu.sv:1012–1027`)

```systemverilog
scr1_pipe_bpred #(...) i_bpred (
    .bp_instr_i (...),                // биты команды с головы очереди
    .bp_pc_i    (ifu_head_pc),        // теневой PC этой команды (см. [интеграцию](05_integration.md))
    .bp_vd_i    (...),
    .bp_predict_taken_o (bp_predict_taken),
    .bp_predict_pc_o    (bp_predict_pc),
    .bp_is_branch_o     (bp_is_branch),
    .bp_bht_valid_i     (bht_valid),   // ← из [BHT](03_bht.md), главный порт чтения
    .bp_bht_taken_i     (bht_taken) );
```
Выходы уходят в общий арбитраж `bp_any_taken/bp_any_target` (см. [интеграцию](05_integration.md)),
где конкурируют с предсказанием возврата от RAS.

## 5. Почему так, и как можно было иначе

| Решение | Почему так | Альтернатива и её цена |
|---|---|---|
| **BTFN как базовый слой** | бесплатно (нет памяти), верно ловит циклы (backward=взят), даёт разумный дефолт пока BHT не обучен | *always-not-taken*: плохо на циклах; *always-taken*: плохо на forward-ветках; *без статики*: у необученных записей BHT нет направления вовсе |
| **Вычислять цель (PC+imm), а не кэшировать** | на выходе очереди биты команды уже есть → смещение извлекается напрямую | кэш (как BTB): нужен только там, где цель нужна *до* декода; здесь избыточен |
| **Чисто комбинационный** | нет состояния → нет логики отката, EXU арбитр | конвейеризовать: не нужно на 3-ступенчатом ядре |
| **BHT переопределяет BTFN по `valid`** | молодые записи используют статику, зрелые — историю; плавный переход | всегда BHT: холодные записи предсказывали бы мусор до обучения |
| **Параметры фаз (JAL→+cond→+RVC)** | инкрементальный ввод и раздельная отладка/замер вклада | всё сразу: сложнее ловить регрессии |
| **Переиспользовать извлечение imm из Ibex** | верифицированный код раскладки B/J/CB/CJ | писать своё: риск ошибок в раскидке битов смещения |

---

## Резюме одной строкой

BTFN — дешёвый комбинационный слой на выходе очереди: по opcode опознаёт
переход/джамп, извлекает смещение и считает `PC+imm` (цель), а направление берёт от
[BHT](03_bht.md) (если обучен) либо по знаку смещения (backward=взят). Он даёт корректный
дефолт без памяти и служит fallback'ом для динамики; его `bp_is_branch` нужен BTB
для проверки steered-переходов на выходе очереди.
