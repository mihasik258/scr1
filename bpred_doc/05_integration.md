# Часть 5 — Интеграция: как всё соединяется в IFU

Файл: `scr1_pipe_ifu.sv` (арбитраж), `scr1_pipe_exu.sv` (арбитр корректности),
`scr1_pipe_top.sv` (проводка каналов). Связывает [BTB](01_btb.md), [BTFN](02_btfn.md),
[BHT](03_bht.md), [RAS](04_ras.md).

---

## 0. Общая картина: два места предсказания + один арбитр

```
                 ┌──────────────────────── IFU ─────────────────────────┐
   память ──────►│  fetch-адрес           очередь           голова оч.   │
                 │  imem_addr_ff           слов          ifu_head_pc      │
                 │      │                                    │            │
                 │  [РАННЕЕ]                              [ПОЗДНЕЕ]        │
                 │   BTB(§01) ── steer ──► меняет          BTFN(§02)       │
                 │   + BHT-гейт(§03)       след. адрес     + BHT(§03)      │──► IDU ──► EXU
                 │                         (без флаша)      + RAS(§04)     │        (§0 арбитр
                 │                                          └─► redirect   │         истины)
                 └───────────────────────────────────────────────────────┘
```
- **Раннее** предсказание (BTB на `imem_addr_ff`) — убирает пузырь *на выборке*,
  меняя лишь следующий адрес фетча, без флаша очереди.
- **Позднее** предсказание (BTFN+BHT+RAS на `ifu_head_pc`) — штатный редирект, когда
  переход дошёл до головы очереди; ловит всё, что BTB рулить не может (RVC-стена,
  возвраты).
- **EXU** — единственный источник истины: реальный mispredict перекрывает всё.

---

## 1. Теневой PC (`ifu_head_pc`) — `scr1_pipe_ifu.sv:850–871`

Очередь фетча хранит **слова**, а не PC. Позднему предсказателю нужен **настоящий
PC** команды на голове очереди — чтобы посчитать `PC+imm` (BTFN), проиндексировать
BHT (`pc[10:1]`) и адрес возврата RAS. Его ведёт «теневой» регистр:
```systemverilog
ifu_head_pc_upd = exu2ifu_pc_new_req_i | bp_redirect_req | bp_instr_consumed;
ifu_head_pc <= exu2ifu_pc_new_req_i ? exu2ifu_pc_new_i           // редирект EXU
             : bp_redirect_req ? (bp_steer_misfetch ? bp_seq_pc   // misfetch → seq
                                                     : bp_any_target) // поздний редирект → цель
             : bp_steer_commit ? bp_predict_pc                    // steered-taken: цель уже в очереди
             : ifu_head_pc + (q_head_is_rvc ? 2 : 4);             // иначе += длина команды
```
Инвариант: в момент consume `ifu_head_pc` обязан равняться `pc_curr_ff` в EXU —
иначе индекс BHT/цель разъедутся с реальностью.

---

## 2. Сбор общего предсказания (`scr1_pipe_ifu.sv:1089–1093`)

BTFN и RAS объединяются в одну пару «взят/цель»:
```systemverilog
bp_any_taken  = bp_predict_taken | ras_predict_vd;          // взят: ветка/джамп ИЛИ возврат
bp_any_target = ras_predict_vd ? ras_top : bp_predict_pc;   // цель: вершина RAS важнее BTFN
```
Возврат (RAS) переопределяет цель, потому что для `ret` BTFN-цель (`PC+imm`)
бессмысленна — цель косвенная.

## 3. Условие редиректа и роль BTB-commit (`scr1_pipe_ifu.sv:1096–1120`)

```systemverilog
bp_redirect_req = bp_instr_consumed & ~exu2ifu_pc_new_req_i
                & ( (bp_any_taken & ~bp_steer_commit)   // поздний взятый, ЕЩЁ не порулленный BTB
                  |  bp_steer_misfetch );               // BTB порулил, но BHT/BTFN сказал «не взят»
pc_new_req_i2 = exu2ifu_pc_new_req_i | bp_redirect_req; // редирект в датапас IFU (EXU выигрывает)
pc_new_i2     = exu2ifu_pc_new_req_i ? exu2ifu_pc_new_i
              : bp_steer_misfetch     ? bp_seq_pc        // откат на последовательный путь
                                      : bp_any_target;
```
Три случая на выходе очереди для перехода:
| ситуация | что делаем | цена |
|---|---|---|
| поздний «взят», BTB **не** рулил (`~steer_commit`) | флаш + редирект на цель (штатный D1) | пузырь взятого перехода |
| BTB рулил и BHT/BTFN согласны «взят» (`steer_commit`) | **флаша НЕТ** — цель уже в очереди за переходом | 0 (это и есть выигрыш §01) |
| BTB рулил, но поздний сказал «не взят» (`steer_misfetch`) | флаш на `bp_seq_pc` (притащили цель зря) | штраф misfetch |

Благодаря fetch-side гейту (§03 §4.2) третий случай на практике сведён к нулю.

## 4. Круговорот обучения (fetch → EXU → train)

Оба обучаемых элемента тренируются **из EXU на retire**, но по данным, посчитанным
раньше:
- **BHT** (§03 §4.3): индекс `ifu_head_pc[10:1]` едет с командой в EXU
  (`ifu2exu_bp_index`), возвращается как `exu2ifu_bp_upd_index` — обучается **ровно
  предсказавшая запись**; `taken = branch_taken`.
- **BTB** (§01 §4.7): `pc_curr_ff`, `jb_new_pc`, `safe`, `is_cond` — только прямые
  взятые переходы, один импульс на `exu_rdy`.

Каналы `exu2ifu_bp_upd_*` и `exu2ifu_bp_btb_upd_*` проходят через
`scr1_pipe_top.sv` (§01 §4.8).

## 5. Порядок приоритетов (кто кого перекрывает)

```
EXU-редирект (истина)                         ← всегда выигрывает (pc_new_req_i2, pc_new_i2)
  > BTB steer-commit                          ← подавляет поздний флаш (цель уже в очереди)
  > BTB steer-misfetch                        ← флаш на seq (откат ошибочного steer'а)
  > поздний BTFN/BHT/RAS редирект (bp_any)    ← штатный редирект на цель
  > ранний BTB steer (imem_addr_next)         ← меняет след. адрес фетча, без флаша
  > последовательная выборка (PC + длина)     ← дефолт
```
Ключевой инвариант всей связки: **любой предсказатель — только подсказка.** Ошибка
любого из них максимум стоит такта(ов) флаша; функциональную корректность всегда
восстанавливает EXU через `exu2ifu_pc_new_req_i`. Поэтому ни у одного элемента нет
логики отката/чекпоинтов — это и делает связку дешёвой и безопасной.

## 6. Конфигурация (какие `define` что включают)

`scr1_arch_description.svh`:
| define / параметр | включает |
|---|---|
| `SCR1_BPRED_EN` | базовый BTFN (§02) + поздний редирект |
| `SCR1_BP_DYNAMIC` | динамический BHT (§03), fallback на BTFN |
| `SCR1_BP_RAS` + `SCR1_RAS_DEPTH` | RAS (§04) |
| `SCR1_BP_BTB` + `SCR1_BP_BTB_SIZE` | ранний BTB (§01) + fetch-side гейт |
| `SCR1_BP_BHT_SIZE`/`_IDX_W` | размер/индекс BHT |
| `SCR1_IFU_QUEUE_SIZE_WORD` | глубина очереди фетча (**параметр фронтенда, не предсказателя**; влияет на runway для steer'а) |

Все части — под `ifdef`, поэтому конфигурации от «чистого BTFN» до «BTB+BHT+RAS»
собираются без правки RTL, и вклад каждой можно мерить отдельно.

---

## Резюме одной строкой

IFU держит два места предсказания — раннее (BTB меняет адрес фетча без флаша) и
позднее (BTFN+BHT+RAS редиректят на выходе очереди по теневому `ifu_head_pc`), — а
EXU остаётся арбитром истины. `bp_steer_commit` связывает раннее и позднее (steered
переход не флашится), обучение обоих таблиц идёт из EXU по данным, посчитанным на
фетче, и ни один элемент не хранит спекулятивного состояния.
