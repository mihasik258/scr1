# Рекомендованные значения предсказателя SCR1 (по классам задач)

Практический выбор параметров предсказателя под цель **максимум выигрыша при
минимуме площади**. Основано на замерах verilator (CFG=RV32IMC_MAX, 16 Embench +
CoreMark/qsort, все CRC/verify-проверены). Полные данные —
[optimization_study.md](optimization_study.md), [embench_suite.md](embench_suite.md),
[trace_accuracy.md](trace_accuracy.md).

## 1. Базовый набор (рекомендуется по умолчанию)

Покрывает практически все задачи; по циклам равен куда бОльшим таблицам.

| Параметр | Значение | Размер | Почему |
|---|---|---|---|
| `SCR1_BP_BHT_SIZE` | **128** | 0.25 Кбит | по циклам = 1024 для 15 из 16 бенчей |
| `SCR1_BP_BTB_SIZE` | **64** (128 с запасом) | ~4–9 Кбит | BTB=64 стоит ≤1 % по 16 Embench (slre/nsichneu), у 14/16 ~0 |
| `SCR1_RAS_DEPTH` | **4** | ~0.1 Кбит | подтв. на Embench: RAS=2 стоит ≤0.11 %, RAS=8 даёт ≤0.01 % |
| `SCR1_BP_GSHARE` | **выкл** | — | точность растёт, но циклы ухудшаются (рассинхрон fetch-гейта) |
| `SCR1_IFU_QUEUE_SIZE_WORD` | **4** (если допустимо) | — | параметр ядра, но главный рычаг циклов (−13 % CoreMark) |

Предсказатель-only на этом наборе (vs ядро без BPU, queue=2) — от −0.1 % до −18 %
по бенчам, агрегат ≈ −5.4 %.

## 2. Спец-профиль: автоматы состояний / сильный алиасинг

Единственный класс, где **больший BHT реально даёт циклы** — код с очень большим
числом промахов при малой таблице (много статических веток, тесно
разложенных по PC: генерируемые автоматы, интерпретаторы).

| Параметр | Значение | Доп. выигрыш |
|---|---|---|
| `SCR1_BP_BHT_SIZE` | **4096** (колено, 8 Кбит) | −2.9 % циклов сверх базы |
| | 16384 (32 Кбит) — максимум | −3.9 % |

Пример (nsichneu): предсказатель-only −4.3 % при BHT 128 → **−9.1 % при BHT 4096**;
mispred 111099 → 196.

## 3. Как определить класс задачи

1. Прогнать с `-DSCR1_BP_PROFILE`, посмотреть `mispred` при базовом BHT=128.
2. Прогнать с BHT=4096.
   - **`mispred` резко падает (в разы) И циклы заметно снижаются (>1 %)** → это
     алиасинг-класс, ставить BHT 4096.
   - **`mispred` падает, но циклы почти не меняются** → точность не конвертируется
     (compute/frontend-bound), оставить BHT 128.
   - **`mispred` уже мал / не меняется** → база, BHT 128.

Ключевой критерий — не точность сама по себе, а **конвертируется ли она в циклы**.
На SCR1 (3-ступенчатое in-order, промах ~2–3 такта, узкое место — фронтенд) большинство
задач в размер таблицы не упирается.

## 4. Данные (Δ циклов от размера BHT, queue=2)

| бенч | BHT 128 | 1024 | 4096 | 16384 | класс |
|---|---|---|---|---|---|
| **nsichneu** | +2.4 % | 0 | **−2.9 %** | **−3.9 %** | алиасинг → 4096 |
| остальные 15 | ~0 | 0 | ~0 | ~0 | насыщены → 128 |

(«остальные 15»: sglib, ud, huffbench, aha-mont64, slre, wikisort, md5sum,
matmult-int, statemate, edn, tarfind, depthconv, nettle-aes, nettle-sha256, crc32 —
все в пределах ±0.6 % по размеру BHT.)

## 5. Не-рычаги (проверено, не тратить площадь)

- **Размер таблиц сверх базы** — на 15/16 задач по циклам бесполезен.
- **gshare / глобальная история** — улучшает точность, ухудшает циклы.
- **RAS глубже 8** — насыщение.
- Точность направления имеет запас (BHT SCR1 87.9 %, потолок TAGE 98 %), но на SCR1
  **не конвертируется** — гнаться за ней нерационально (см. [trace_accuracy.md](trace_accuracy.md)).
