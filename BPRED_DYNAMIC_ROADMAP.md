# Дорожная карта: адаптация динамического предсказателя CVA6 (BHT+BTB+RAS) в SCR1

Цель: перенести связку предсказателей CVA6 в SCR1 — быстро и корректно —
с учётом различий конвейеров. Источники: `core/frontend/{bht,btb,ras,frontend}.sv`
(OpenHW CVA6, Solderpad/Apache-2.0) + документация PC-gen / IF stage.

================================================================================
## 0. Что такое предсказатель CVA6 (факты из исходников)
================================================================================

Три независимые структуры, каждая под свою задачу:

- **BHT** (`bht.sv`, по умолч. NR_ENTRIES=1024): направление условной ветки.
  2-битные счётчики насыщения, индекс по битам PC. Выход — МАССИВ
  `bht_prediction_o[INSTR_PER_FETCH-1:0]` (по предсказанию на инструкцию блока).
  Обновление `bht_update_i` = {pc, taken} со стадии исполнения.
  Правило счётчика: 11 строго-взят, 00 строго-не-взят, промежуточные ±.

- **BTB** (`btb.sv`, по умолч. NR_ENTRIES=8): адрес цели КОСВЕННОГО прыжка (JALR).
  Хранит target по индексу PC + тег (против алиасинга). Обновляется ТОЛЬКО
  при промахе JALR: `btb_update.valid = resolved.valid & is_mispredict & cf_type==JumpR`.

- **RAS** (`ras.sv`, по умолч. DEPTH=2): адрес возврата (`ret`). Простой стек-сдвиг:
  `push_i`/`pop_i`/`data_i`, выход `data_o` (вершина). `flush_bp_i` очищает весь стек.
  ВАЖНО: точного восстановления НЕТ — при промахе RAS просто очищается флашем.

Комбинирование (PC-gen, приоритетный mux): BHT даёт направление; если запись BHT
невалидна → **статический BTFN fallback** (по знаку смещения); BTB даёт цель JALR;
RAS даёт адрес возврата. `bp_valid` подставляет предсказанный адрес в `npc`.

Путь обновления: сигнал `resolved_branch_i` (тип `bp_resolve_t`) со стадии
исполнения (branch unit) → `bht_update`/`btb_update`. То есть обучение — на
РАЗРЕШЕНИИ ветки, не на коммите.

================================================================================
## 1. ГЛАВНЫЙ "подводный камень": разные конвейеры
================================================================================

| Аспект | CVA6 | SCR1 |
|---|---|---|
| Глубина | 6 стадий, decoupled frontend | 2-3 стадии |
| Предсказание | на стадии **PC-gen**, ДО выборки, по **одному PC** | на выходе очереди IFU, ПОСЛЕ сборки инструкции |
| Что индексирует таблицу | сам PC (инструкция ещё не известна) | `ifu_head_pc` (теневой PC) + биты инструкции |
| Ширина | суперскаляр: массив на блок `INSTR_PER_FETCH` | скаляр: одна инструкция |
| Выборка | блок 32 бит (2 RVC), реалайн позже | полуслова в очередь |
| Восстановление | kill_s1/s2 icache + npc | flush очереди + `exu2ifu_pc_new_req` |
| Обновление | `resolved_branch_i` со стадии исполнения | наш EXU (`jb_taken`/`branch_taken`) |
| Типы | `config_pkg::cva6_cfg_t`, `ariane_pkg::*` | plain SV (как мы делали с ibex_pkg) |

Отсюда два уровня адаптации:

- **Уровень A (умеренный, рекомендуется начать):** оставляем точку предсказания на
  выходе очереди IFU (как сейчас у статики), но ЗАМЕНЯЕМ источник направления на
  динамический BHT (индекс по `ifu_head_pc`). Переиспользуется ВСЯ наша инфраструктура
  (теневой PC, цель `PC+imm`, redirect/recovery). Выигрыш по тактам тот же (~1 такт/ветка),
  но ТОЧНОСТЬ выше (динамика вместо BTFN). Низкий риск.

- **Уровень B (глубокий, позже):** перенести предсказание на стадию адреса выборки
  (`imem_addr_ff`), индексировать BHT/BTB по адресу выборки ДО прихода инструкции —
  как PC-gen в CVA6. Ближе к нулевому пузырю. Требует переработки IFU (prefetch-queue →
  логика PC-gen). Высокий риск/выигрыш.

Рекомендация: BHT сначала на Уровне A, затем при желании Уровень B.

================================================================================
## 2. Второй "камень": зеркало в EXU умирает
================================================================================

Сейчас EXU ПЕРЕСЧИТЫВАЕТ предсказание из битов инструкции (`bp_taken`), потому что
статика — чистая функция инструкции. С динамикой НЕЛЬЗЯ: предсказание зависит от
СОСТОЯНИЯ таблицы BHT на момент выборки, которого EXU не знает.

Следствие (центральная переделка динамики):
1. Убрать зеркало `bp_taken` в EXU.
2. Пронести по конвейеру ВНИЗ (IFU → `exu_queue` → EXU) вместе с инструкцией:
   - `bp_predicted_taken` (1 бит) — что предсказали;
   - `bp_index` (лог2(NR_ENTRIES) бит) — индекс BHT, для обучения;
   - (для RAS/BTB позже — `bp_is_call/is_ret`, предсказанную цель).
3. В EXU: `mispredict = actual_taken ^ bp_predicted_taken` (теперь по пронесённому биту).
4. Добавить путь ОБУЧЕНИЯ: EXU формирует `resolved_branch` = {index, taken, valid} →
   в IFU обновляет счётчик BHT. Аналог `bht_update_i` в CVA6.

Инфраструктура redirect/recovery (`pc_new_req_i2`, `bp_recover_seq`, развязка
`pc_curr_transfer`) остаётся без изменений.

## 3. Фазовый план
================================================================================

### Фаза D0 — переключатель и каркас (без функционала)
- Добавить `SCR1_BP_DYNAMIC` рядом с `SCR1_BPRED_EN` (в scr1_arch_description.svh).
  Матрица:
    BPRED_EN=0            → оригинал (baseline)
    BPRED_EN=1, DYNAMIC=0 → статический BTFN (текущее)
    BPRED_EN=1, DYNAMIC=1 → динамический BHT (+BTFN fallback)
- Ввести проброс `bp_predicted_taken`/`bp_index` по IFU→IDU→EXU (пока не используется).
- Ввести пустой канал обучения EXU→IFU.
- Проверка: DYNAMIC=0 → 56/56 как сейчас (регресса нет).

### Фаза D1 — BHT (направление), Уровень A  ← ОСНОВНОЙ шаг
Взять `bht.sv` из CVA6, адаптировать:
- Убрать `config_pkg`/`ariane_pkg`, заменить типы на plain SV (как с ibex_pkg).
- **Скаляризовать:** INSTR_PER_FETCH=1 → убрать массив `[INSTR_PER_FETCH-1:0]`,
  оставить один выход {valid, taken}.
- Индекс = `ifu_head_pc[log2(NR)+OFF-1 : OFF]`, где OFF учитывает 2-байтовое
  выравнивание RVC (младший бит PC всегда 0 → индексировать с бита 1).
- Вход обновления `bht_update` = {index/pc, taken} из канала обучения EXU.
- FPGA-вариант памяти: для Nexys — распределённая память/регистры; на 1024×2 бит
  можно регистрами. `flush_bp` (у нас — сброс/редирект) очищает valid-биты.
- В `scr1_pipe_bpred`: под `SCR1_BP_DYNAMIC` направление берётся из BHT; если
  запись невалидна → текущий BTFN (`imm[31]`) как fallback (как в CVA6).
- Цель по-прежнему `ifu_head_pc + imm` (наш сумматор). JAL — по-прежнему always-taken.
- EXU: зеркало → сравнение с пронесённым `bp_predicted_taken`; сформировать `resolved`.

Подводные камни D1:
- Read-during-write BHT: обновление и чтение в один такт — выбрать поведение
  (bypass или старое значение). В нашем медленном ядре проще регистровая таблица.
- Задержка обучения: ветка обновляет счётчик через 1-2 такта после предсказания;
  на тесном цикле первые итерации могут не успеть — это нормально (точность растёт).
- Инвариант `ifu_head_pc == pc_curr_ff` по-прежнему обязателен (индекс и обучение
  должны сходиться на одном PC).

Проверка D1: `riscv_isa` 56/56; dhrystone/coremark — сравнить точность и такты
со статикой (ожидаем лучше на непредсказуемых ветвлениях).

### Фаза D2 — RAS (возвраты)
- Взять `ras.sv` (простой стек, DEPTH 2-8). Убрать pkg-типы.
- Детект call/ret по RISC-V ABI: call = JAL/JALR с rd∈{x1,x5}; ret = JALR с rs1∈{x1,x5},
  rd=x0. Определяется из битов инструкции в IFU.
- push при call (инструкция ушла в IDU), pop при ret → предсказанная цель = вершина RAS.
- Теперь мы ВПЕРВЫЕ предсказываем JALR-возвраты (раньше не предсказывали вовсе).
- Подводный камень (главный): СПЕКУЛЯТИВНАЯ порча RAS. Между предсказанием и
  разрешением RAS уже изменён. У CVA6 точного отката нет — только `flush_bp` очищает
  стек. Минимально: на любом redirect/промахе очищать RAS (как CVA6). Точный откат
  (сохранять/восстанавливать указатель) — опционально, сложнее.
- EXU: для ret сравнить факт-цель с вершиной RAS → mispredict → redirect на факт.

Проверка D2: тесты с вложенными вызовами/рекурсией; убедиться, что после промахов
RAS-очистка не ломает корректность (EXU всегда исправляет цель).

### Фаза D3 — BTB (косвенные прыжки, кроме ret)
- Взять `btb.sv` (NR_ENTRIES 8-32). Скаляризовать, убрать pkg.
- Хранит {tag, target} по индексу PC. Предсказывает цель JALR (не-ret).
- Обновление ТОЛЬКО при промахе JALR (как в CVA6): `resolved.is_mispredict & JumpR`.
- Тег обязателен (алиасинг из-за малого размера).
- Подводный камень: JALR-цель = rs1+imm неизвестна на выборке — BTB её ХРАНИТ из
  прошлых исполнений. Первый вызов всегда промах (cold), обучаем.

Проверка D3: косвенные вызовы (switch/таблицы функций, указатели).

### Фаза D4 — опции (по желанию)
- gshare: XOR индекса BHT с регистром глобальной истории (GHR). GHR спекулятивно
  обновляется, откатывается на промахе — ещё один камень со спекуляцией.
- Уровень B: перенос предсказания на адрес выборки (PC-gen-стиль) для нулевого пузыря.
- bht2lvl.sv (двухуровневый BHT) из CVA6.

## 5. Порядок работ (итог)
================================================================================

1. D0: переключатель `SCR1_BP_DYNAMIC` + каналы проброса/обучения (регресс 56/56).
2. D1: BHT-направление (Уровень A) — главный шаг, даёт точность. Зеркало → пронос бита.
3. D2: RAS-возвраты.
4. D3: BTB-JALR.
5. D4: gshare / Уровень B / bht2lvl — по потребности.

Каждая фаза: `SCR1_BP_DYNAMIC=0` должна оставлять статику нетронутой (A/B),
`SCR1_BPRED_EN=0` — оригинал. После каждой фазы: `riscv_isa` 56/56 + замер точности.
